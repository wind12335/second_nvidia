# NVSHMEM A800 准入诊断记录（2026-09-02）

> 事件：A800 会话首次 admission smoke 失败 → 系统化定位 → 根因锁定 wheel 库 bug → 对策=源码重编。
> 诊断工具：`second_nvidia/nvshmem_phaseB/src/mini_sig.cu`（自研最小复现器，6 种模式，全部可复跑）。
> 红线遵守：失败 case 原样保留在 `nvshmem_phaseB/results/admission_smoke_20260902T*/`。

## 1. 现象链（全部有日志）

| # | 实验（mini_sig 模式） | 结果 | 含义 |
|---|---|---|---|
| 1 | admission smoke A2（wheel 3.6.5） | exit 255：putget.cpp:88 `cuda failed with invalid argument`，abort 在 nvshmemx_putmem_signal_on_stream | **NVSHMEM init 在 A800 上成功**（4090 三重锁死解除），挂在 host put_signal |
| 2 | self_on_stream（自发给自己） | issue 成功，无 CUDA 错误 | on_stream 机制本身 + wheel 的 memcpy+signal 路径对本地指针正常 |
| 3 | on_stream（发 peer，VMM 堆默认） | 同 #1 invalid argument；nvshmem_ptr(peer) = 本地 VA +256GB（VMM 区射） | 跨 PE 才失败 |
| 4 | NVSHMEM_DISABLE_CUDA_VMM=1 | 堆切到裸 cudaMalloc（peer 返回原始设备指针，delta -2.5GB），**同样失败** | 与堆类型无关 |
| 5 | EXPLICIT_P2P（显式 cudaDeviceEnablePeerAccess，两种堆） | enable OK，**仍失败** | 与 peer access 状态无关 |
| 6 | NVSHMEM_REMOTE_TRANSPORT=none（纯 P2P transport） | 仍失败 | 与 IB/transport 选择无关 |
| 7 | device_put（device API 路径，两种堆） | put 后 quiet 报 **illegal memory access** | device 路径同病：跨 PE 访问崩上下文 |
| 8 | **raw_memcmp（裸 CUDA，同指针同流同进程）** | cudaMemcpyAsync(D2D,peer)=**Success**；cudaMemcpyPeerAsync=**Success**；payload 校验 **PASS** | **容器/驱动/P2P 全部健康，故障只在 wheel 内部** |

## 2. 根因判定

- wheel `nvidia-nvshmem-cu12==3.6.5` 按其报错路径（`r12.9` = CUDA 12.9 工具链）编译；
  本机 CUDA 12.6.85 运行时 + 驱动 580.65.06。同进程内 wheel 与应用各自解析 CUDA 运行时，
  出现"裸 CUDA 成功、wheel 同调用 invalid argument / IMA"的分裂行为。
- 判定依据链：#8（裸 CUDA 通过）⇒ 环境无罪；#3–#6（堆/enable/transport 全排除）⇒ 非配置问题；
  #7（device 路径同病）⇒ wheel 的 host+device 两个库一体的问题。
- 分类：**平台-库兼容缺陷**，不是我们代码问题（指针构造经 nvshmem_ptr 正确性在 #8 复用验证）。

## 3. 对策（执行中）

用扩展包携带的 NVSHMEM 源码快照（e937b47，2026-07-28 主线，即完成语义笔记所读源码，
版本 3.8.0.dev0）现场编译，动态链接本机 CUDA 12.6：
`build-sm80`：Release / sm_80 / P2P_ONLY=ON / 跳过 examples、tests、hydra、包。
安装前缀 `/root/nvshmem-src-prefix`。完成后 admission 用 `NVSHMEM_PREFIX=/root/nvshmem-src-prefix` 重建。

## 4. 影响与对策有效性预判

- 若源码版 put_signal 通过 smoke → admission 走源码版 NVSHMEM，wheel 弃用并在平台表记录原因；
- 若源码版同故障 → 问题指向驱动 580 open 模块 + CUDA 12.6 组合，升级 CUDA 12.9 工具链（源码重编）
  为第二方案；nsys 后续也需 apt 直连解决（见平台快照 §5）。
- 论文角度：这一段是"跨基座能力差异"的又一实证——NVIDIA 侧 PGAS 路径的可用性本身
  依赖库-运行时版本矩阵，capability profile 必须记录 NVSHMEM 精确版本与构建来源（源码 hash）。
