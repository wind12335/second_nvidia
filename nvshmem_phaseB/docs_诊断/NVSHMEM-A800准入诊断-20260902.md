# NVSHMEM A800 准入诊断记录（2026-09-02）

> 事件：A800 会话首次 admission smoke 失败 → 系统化定位 → 根因锁定 wheel 库 bug → 对策=源码重编。
> 诊断工具：`second_nvidia/nvshmem_phaseB/src/mini_sig.cu`（自研最小复现器，6 种模式，全部可复跑）。
> 红线遵守：失败 case 原样保留在 `nvshmem_phaseB/results/admission_smoke_20260902T*/`。

## 2. 根因判定（2026-09-02 22:20 修正版——推翻早前"wheel bug"结论）

**真实根因：移植代码的 NVSHMEM API 契约错误（我方 bug，非 wheel、非环境）。**

- NVSHMEM 的 put/signal 系 host API 契约：**传本地对称地址**，库内部经
  `MAPPED_PTR_TRANSLATE = local_pe_bases[peer] + (ptr − heap_base)`（src/include/internal/host/util.h:149）平移到目标 PE。
- 我们的移植（照搬 DUSHMEM Phase A 的 nvshmem_ptr 风格）先 `nvshmem_ptr()` 翻译成远端 VA 再传入
  ⇒ 库内二次平移（+256GB 出映射窗）⇒ cudaMemcpyAsync(D2D) invalid argument；device 路径同理 IMA。
- 证据闭环：mini_sig 同指针同流自调 cudaMemcpyAsync PASS（#8）+ 改传本地对称地址后
  wheel 3.6.5 与源码版 (e937b47/3.8.0.dev0) **双双全尺寸 PASS**（8B/4KB/64KB）；
  admission smoke 4 case 全 PASS（put_signal / quiet / credit+slot / fcollect，0 校验错，4 卡）。
- 早前把矛头指向 wheel(r12.9 构建 vs 本机 12.6) 的推断**不成立**——两库行为一致，均为调用方错误。
  保留此误判过程作为记录：跨基座移植时"API 名称相同"不等于"地址契约相同"，这正是
  手册-源码-实测三层证据法的价值（DUSHMEM 的 put 收 dushmem_ptr 结果，NVSHMEM 收对称地址——契约相反！）。
- 附带修复：run_admission.sh 两处 bash 陷阱（`(( x += 0 ))` 触发 set -e；mpirun 吞 while 循环 stdin）；
  admission 横幅硬编码 sm_89 → 运行时查询（现打印 sm_80 + API 版本）。

## 3. 对策（执行中）

用扩展包携带的 NVSHMEM 源码快照（e937b47，2026-07-28 主线，即完成语义笔记所读源码，
版本 3.8.0.dev0）现场编译，动态链接本机 CUDA 12.6：
`build-sm80`：Release / sm_80 / P2P_ONLY=ON / 跳过 examples、tests、hydra、包。
安装前缀 `/root/nvshmem-src-prefix`。完成后 admission 用 `NVSHMEM_PREFIX=/root/nvshmem-src-prefix` 重建。

## 4. 最终结局（22:25 更新）

- admission 选定 **wheel 3.6.5**（与 4090 计划一致的 pip 锁定版）；源码版 e937b47 留作源码阅读/后备，
  构建产物在 /root/comm-study/nvshmem/build-sm80 + /root/nvshmem-src-prefix。
- smoke 4/4 PASS（见 results/admission_smoke_20260902T141941Z），formal 进行中。
- 论文角度：本案是比"版本矩阵"更有价值的素材——**同族 API（DUSHMEM put vs NVSHMEM put）地址契约相反**，
  capability profile 里必须为每基座记录"对称地址 vs 已翻译地址"这一契约维度，跨基座 selector 的
  strategy contract 也须显式包含它。
- nsys 仍缺（apt 直连失败，需离线 deb 或直连源），不阻塞 admission/port，trace 阶段前解决。
