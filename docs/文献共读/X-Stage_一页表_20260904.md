# X-Stage 一页证据表（2026-09-04）

> 论文：*X-Stage: An Overlooked Pipeline Stage for Communication–Computation Overlap in DiT Inference*，arXiv:2607.23264。依据为本地 19 页全文及带页码文本；PDF SHA256 见 extraction manifest。

## 问题与机制

- 论文把 one-sided remote store 的 sender 侧拆成“指令被接受”和“远端可见”两个事件，并把二者之间仍可与后续计算并发推进的阶段命名为 X-Stage（p.2–4）。
- Burst–Gap 模型用无背压 issue 时间 `Tiss0(K,V)`、有效排空率 `R`、有效 outstanding capacity `Q(K)` 描述 sender-visible stall（p.5–6）：
  - `Tiss(G;K,V)=max(Tiss0(K,V), V/R-G)`；
  - `ΔTiss=[V/R-G-Tiss0]+`；
  - 恢复阈值 `G*=[V/R-Tiss0]+`；
  - 单 burst 无背压还要求 `[V-R*Tiss0]+ <= Q(K)`。
- 论文在 8-GPU NVIDIA 节点上测得短 burst 可在 issuer 恢复计算后继续排空，持续注入则耗尽有限容量并反压后续 issue（p.1, p.5–6）。

## 对本项目的排重与价值

- 不能再把“issue 与 remote-visible completion 分离”或 sender 侧 burst/drain/capacity 模型作为本项目独有发现。
- 它直接支持我们的元结论：模型形式可能保留，但拓扑、路由、store 宽度、producer 数、内存放置或 GPU 代际改变时参数需重标（p.16）。
- 它明确声明 drain horizon 不替代 fence、memory ordering、buffer lifetime 和 consumer readiness；当前证据只覆盖 one-sided remote stores，不覆盖不同 progress engine 的 collectives、loads、atomics 与跨节点路径（p.16）。

## 可保留差异

本项目应把统一时间线写成：

`issue → sender accepted/backpressure（X-Stage） → remote visible → consumer legal release R_i → GEMM actual consume`。

我们的主张限于 X-Stage 之后的 consumer-side legal release、CCL/PGAS 库路径的完成语义差异、跨策略族选择与少量稳健探针；不是重新命名 sender-side X-Stage。
