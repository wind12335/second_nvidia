# Perseus / Hidden Serialization 一页证据表（2026-09-04）

> 论文：*Eliminating Hidden Serialization in Multi-Node Megakernel Communication*，arXiv:2605.00686。依据为本地 16 页全文及带页码文本。

## 核心发现

- 在 proxy-based RDMA transport 中，`PUT-WITH-SIGNAL` 被展开为 `PUT → FENCE → SIGNAL`；每个 fence 等待 channel 中此前 PUT 完成，导致并发 CTA 的细粒度通知把共享 proxy FIFO 串行化（p.6–7）。
- 96 个并发传输、8 节点时，带 signal 的吞吐可降到 put-only 的 2%；小消息中 fence 可占通信时间 98%，signal 自身反而低于 0.2%（p.6）。
- 这说明“通知越细越能重叠”并不成立：保证 payload-before-signal 的 ordering 机制可能成为重叠瓶颈。

## Perseus 机制

- Decoupled signaling：所有 CTA 先连续提交 PUT，leader 等组内 PUT 均进入 FIFO 后只做一次 FENCE，再批量发该组 signals（p.7–8）。
- NIC-side ordering：把 ordering 放到 NIC fence flag，而不是让 proxy 主动 drain/阻塞（p.8）。
- group size 暴露 fence amortization 与等待更多 outstanding PUT 的权衡；per-destination/PE 分组在其实验中接近曲线 knee（p.8）。

## 对本项目的排重

- 不能把“批量 signal / 减少 fence 次数”本身包装成独有贡献。
- 论文方向主要是多节点 MoE megakernel 与 proxy RDMA；我们的当前 A800/K500 数据主要是单节点 CCL/PGAS AG→GEMM，因此不能直接外推其 2%/98% 数字。

## 可借鉴假设

把 `signal_group=b` 作为候选维度，并保持总 payload、q、PUT 数和 GEMM partition 不变。可证伪预测：小 `b` 早 release 但 ordering/fence 税高；大 `b` 税低但推迟 `R_i`，端到端对 `b` 可能呈 U 型或阈值型，最优值随基座平移。该方向需新代码和机时，执行前必须单独征求用户。

## 证据等级

全文级直接证据；机制高度相关，但部署范围与本项目当前单节点平台不同，属于强启发而非已验证共同定律。
