## 3. p2p_probe 异常的诚实记录（不掩盖）

p2p_probe 的 `cudaMemcpyPeer` 256MiB 带宽只有 15.3–20.7 GB/s（PCIe 量级），与 NVLink 事实矛盾。
**判定：探针测法伪影，不代表互连**。依据：NCCL 同机 busbw 129+ GB/s（NCCL 走 NVLink P2P），
NVLink 链路在位（nvlink -s 8×25）。可能原因：CE 拷贝单流不足以打满 NVSwitch、或 memcpy 路径
在容器内经 PCIe staging。**对论文的影响：平台互连证据以 NCCL busbw + nvlink -s 为准；
p2p_probe 只用于 canAccessPeer 判定；本异常已记录，不在论文中引用 memcpyPeer 数字。**
（4090 侧该探针 17–19 GB/s 是 host 中转真值，两机语义不同，不可直接对比。）

3. nccl-tests 2026 快照用了 NCCL 2.29+ 的 `ncclCommQueryProperties`，本机 2.28.3 无此符号 →
   已打弱引用+空指针守卫补丁（`platform/nccl_tests_compat_20260902.patch`，同入库）。
4. **nccl-tests 初次构建 MPI=1 实际未链 libmpi**（四进程各自 singleton world、全 Rank0/device0、
   busbw 0 假象）→ `make clean && make MPI=1 MPI_HOME=/usr/lib/x86_64-linux-gnu/openmpi` 后
   ldd 见 libmpi.so.40 才是真值。**教训：每次重建后必须 `ldd | grep mpi` 验尸，假数据已识别未采信。**
